## 2. Evidence method and status key

Automated evidence here means **tests that ran on this commit**, not a live SQL/browser workflow unless the test explicitly says so. Many tests assert source, SQL contracts, or in-process behavior; they do not prove a deployed transaction, UI rendering, persistence, or external integration. Manual evidence means a dated observation on this **current commit** with environment, synthetic tenant/patient IDs held in a protected record, actor/role, steps, expected/actual status, trace/audit correlation and a redacted artifact reference. No current-main manual clinical run was supplied or executed in Step 40. Earlier operator stability reports and [Step 23B runtime work](evidence/security-audit/27-step23b-runtime-validation.md) remain historical evidence, not automatic current-run passes. The [Step 12 runtime ledger](evidence/runtime/step12-security-runtime-results.md) still marks its ten cases `NOT EXECUTED`.

Overall labels below use the requested vocabulary. `RUNTIME EVIDENCE PARTIAL` means a relevant automated contract exists while current live workflow proof is pending; `RUNTIME EVIDENCE MISSING` means only source evidence exists for the specific behavior. `SPECIFICATION INTERPRETATION BLOCKER` and `EXTERNAL/HOSTING EVIDENCE BLOCKER` additionally limit a certification conclusion. There are no capabilities labeled `BOTH COMPLETE` or `MANUAL EVIDENCE COMPLETE` on this revision. A green test count does not upgrade a whole workflow to `AUTOMATED EVIDENCE COMPLETE` when its tests cover only a bounded contract.

For every matrix row, **manual = pending on current main**; the indicated check is a reproducible plan, not an executed result. `—` in the interpretation column means no *specific* unresolved clause was identified for that row, not proof of specification conformance.

## 5. Negative access, concurrency and audit gaps

**Negative access.** Automated permission metadata and middleware tests establish several fail-closed boundaries: missing permission, invalid tenant claim, unresolved clinical actor, cross-patient encounter addendum, and denied security-audit review. They do not demonstrate every live UI control or direct API denial. Current-run gaps remain for Problem, Allergy/NKA, Medication, Prescription, Immunization, Result, Document/PDF, File, Referral, Provider, CPP, Report, Task and administration operations across permitted/denied roles. For each, G must show direct 403 or appropriate 404, no protected data disclosure, no mutation, and no false *success* audit; a governed **denial** event may be expected. Cross-patient and cross-tenant attempts must be exercised against actual separate objects and tenants.

**Concurrency.** Current source/test contracts cover medication **discontinue** 0059, Result update/correction and atomic review, Referral status/follow-up, Provider administration, document draft/content, prescription draft transitions, demographics, allergies, immunizations, files, encounters and key scheduling transitions. A live two-session stale-write proof is still missing for these. Source inspection found `RowVersion` columns but **no client expected-version predicate** in `PatientProblem_Update/Resolve`, `PatientTask_Update/Complete/Reopen`, and `PatientChartAlert_Update/Resolve`. These are source-level coverage gaps, **not runtime defects observed in Step 40**; no product change is made here. Create and idempotent single-transition operations may use other controls and must be assessed by operation, not assumed unsafe because they lack a token. The older [concurrency matrix](evidence/05-concurrency-matrix.md) predates 0059 and must not be read as a current all-domain pass.

**Audit classes and evidence.** Clinical mutation audit uses tenant `AuditLog` for Referral (`ReferralSent`, follow-up, response, close), Provider (create/update/link/status), and Medication `Discontinue`, among other actions. Sensitive-read/disclosure audit separately records `PatientChartOpened`, `PatientDocumentViewed` and `PatientFileDownloaded`. Report disclosure uses `ReportExecuted` and `CsvExported`. Platform security-denial audit records missing permission, invalid tenant membership, cross-patient ownership and unresolved actor. Operational logs report technical failure/status and do **not** replace any governed audit. Tests establish bounded event shape and some cardinality/fail-closed behavior; current live audit persistence, retention, access grants and review have not been observed. Specific gaps include current-run document/PDF/artifact disclosure behavior, all listed mutation event deltas under real SQL, and cross-tenant/denied action absence of false success events. The older [Step 12 audit matrix](evidence/audit-coverage-matrix.md) says downloads were not audited; that statement is historical and superseded by current file-download tests and implementation, pending live verification.
