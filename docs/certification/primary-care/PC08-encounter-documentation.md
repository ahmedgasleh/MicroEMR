## Signed-record and security cross-check

API read/edit/sign operations use `Encounters.View`, `Encounters.Edit`, and `Encounters.Sign`; Web encounter actions carry corresponding Web permission attributes. Stored procedures reject editing/signing from invalid statuses and use row-version concurrency. `PatientEncounterAddendum_Create` accepts signed encounters only and preserves append-only rows in the visible code. Direct SQL grants, absence of undocumented update/delete paths, and rendered authorship must still be verified.
